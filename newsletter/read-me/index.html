The newsletter's HTML: what the two pages are, and how to change the email.

The two pages

  • Blank template: every section and callout, with placeholder words in each slot, so you can see every place an item can go.
  • Sample issue: a fictional issue with every kind of item, as the builder would send it. The builder's Issue list offers the same sample to practice on.

Both are drawn from the builder's own template the moment they open, so they always match what the builder makes. Copy HTML on either page puts that email's code on the clipboard.

Change one email

An issue is built in the Newsletter builder, and every fix goes in its Preview & Tweak step, never in Outlook, so the archive matches what went out. For a change the builder cannot make, press Copy HTML on the Save & Export step, paste the code into Claude, and ask for the change, then paste the result into Outlook. That changes one email only. Example asks:

  • "Move the Opportunities section above Upcoming Events."
  • "Make the Research Brief label maroon instead of gray."
  • "Shorten the introduction to two sentences."

Change the email for good

The email's look lives in one file of the desk's code, builder/js/template.js. A change there reaches the builder, the blank template and the sample at once. To make one, open the desk's folder in Claude Code and ask for the change; it writes the code and runs the desk's tests, and the change goes live when it is pushed. Example asks:

  • "In builder/js/template.js, add a Podcasts section after Headlines."
  • "Change the masthead's date line to read Month Day, Year in small caps."
  • "Give the Share something callout a white button on maroon."

Where the desk's code lives, and who can push it, is in the Policy Exchange hub's handoff.
