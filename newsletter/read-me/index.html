The newsletter's HTML: the two pages, what the builder changes, and when to change the template itself.

The two pages

  • Blank template: every section and callout, with placeholder words in each slot, so you can see every place an item can go.
  • Sample issue: a fictional issue with every kind of item, as the builder would send it. The builder's Issue list offers the same sample to practice on.

Both are drawn from the builder's own template the moment they open, so they always match what the builder makes. Copy HTML on either page puts that email's code on the clipboard.

Change an issue in the builder

Nearly everything about one issue is done in the Newsletter builder, in its Preview & Tweak step, never in Outlook, so the archive matches what went out. The builder can:

  • Put the issue in order: drag a section or an item by its grip. Move to… files an item under another section or group. Remove takes it out, and Undo puts it back.
  • Edit any words in place: a title, a description, the introduction, a callout. Use original and Undo changes put the text back.
  • Choose how an item is laid out: Title and details, With description, Stamp beside the text, Headshot beside it all, or a Date card for an event.
  • Add a picture or a flyer to an item (Add media), and set the picture's size.
  • Set a research item's kind: Research Brief, Research Report, Journal Article or ERC Explains.
  • Add an item by hand, or Add a callout in one of three styles: Maroon block, Light gray box or Dotted rule.
  • Turn the Contents strip on or off. Reset layout puts every option back to its default.
  • Copy HTML into Outlook, then Save to the archive, so Past issues shows the email as it went out.

Change the template itself

Only for a big style change that every issue after should carry: the masthead, the colors and type, a new section, a new layout. The email's look lives in one file of the desk's code, builder/js/template.js, and a change there reaches the builder, the blank template and the sample at once. Open the desk's folder in Claude Code and ask for the change; it writes the code and runs the desk's tests, and the change goes live when it is pushed. Example asks:

  • "Add a Podcasts section after Headlines, with its own label."
  • "Change the masthead to the new ERC banner."
  • "Use a darker maroon for every section rule and button."

If the change is for one issue only, it belongs in the builder. Where the desk's code lives, and who can push it, is in the Policy Exchange hub's handoff.
