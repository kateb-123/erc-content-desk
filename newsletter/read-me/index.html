The newsletter's HTML: the two pages, and when to change the template itself.

The two pages

  • Blank template: every section and callout, with placeholder words in each slot, so you can see every place an item can go.
  • Sample issue: a fictional issue with every kind of item, as the builder would send it. The builder's Issue list offers the same sample to practice on.

Both are drawn from the builder's own template the moment they open, so they always match what the builder makes. Copy HTML on either page puts that email's code on the clipboard.

Change the template itself

Only for a big style change that every issue after should carry: the masthead, the colors and type, a new section, a new layout. The email's look lives in one file of the desk's code, builder/js/template.js, and a change there reaches the builder, the blank template and the sample at once. Open the desk's folder in Claude Code and ask for the change; it writes the code and runs the desk's tests, and the change goes live when it is pushed. Example asks:

  • "Add a Podcasts section after Headlines, with its own label."
  • "Change the masthead to the new ERC banner."
  • "Use a darker maroon for every section rule and button."

A change to one issue belongs in the builder: see Build the newsletter. Who can push a change: Who to ask.
